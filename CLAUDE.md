# healthy

A private health helper template: a remote MCP server (TypeScript, Cloudflare Workers, D1 and KV) that people use through Claude. Setup and how it works are in the README.

- All SQL goes through `src/data/`; every function requires `userId` and scopes by `WHERE user_id = ?`. Tool handlers never write SQL.
- Never accept `user_id` as a tool input; the user comes from the OAuth token.
- Nutrients are computed by the server from grams, never stored on logs and never computed by the model. Only `foods` (per 100 g) hold nutrient numbers (a saved meal is a food with kind `meal`, and the ingredients it was made from are written into its notes); logs hold a pointer and an amount in grams.
- Every nutrient on the standard label (kcal, protein, fat, saturated fat, trans fat, carbs, fiber, sugar, added sugar, cholesterol, sodium) is required wherever nutrients are saved. A value that is not listed is estimated by Claude and the food gets source `estimate`; there are no per-nutrient flags.
- Water is a food, logged with meal type `water` (or with `water_ml` on `log_entries`). There is no water table.
- Never ask for or require gender or sex anywhere in the schema or tools.
- Secrets live in GitHub secrets (production, set by the Deploy workflow) or `.dev.vars` (local, gitignored). Never commit them. Never put an account-specific id, name or URL in the repo.
- Deploys come only from GitHub Actions (`.github/workflows/deploy.yml`), never from a laptop.
- `migrations/0001_schema.sql` is the full schema. Once it has run anywhere, never edit it: add a new numbered migration.
- Layers: zod input shapes and tool text in `src/tools/`; rules that need the database in `src/services/`; SQL only in `src/data/`; pure math in `src/nutrition.ts`.
- Nothing is deleted through the tools: logs, workouts and foods are archived (`archived_at`), and every read of logs and workouts filters `archived_at IS NULL`.
- Logging tools (`log_entries`, `log_workout`) require a `client_request_id`; a repeated id returns the first result (`request_log` table).
- Local commands: `npm run dev` (needs `.dev.vars`), `npm run type-check` (also regenerates `worker-configuration.d.ts`, which is gitignored), `npm test`, `npm run test:scripts`.
- `.wrangler-deploy.json` is generated by the Deploy workflow (`scripts/provision.mjs`) and gitignored. An empty `config/allowed-users.json` fails the deploy.
- When tools change, update the tool list in `docs/reference.md` and the diagrams in `docs/diagrams/` (one file per diagram, same palette).
- Keep it simple: no extra layers, no speculative features. Finish each change with `npm run type-check`, `npm test` and `npm run test:scripts` passing.
